# 功能体验页

## 如何使用

源码启动后，点击控制台顶栏「功能体验」，或访问 `http://127.0.0.1:3000/demo`。桌面版使用相同的组件和入口；已有安装包需要重新构建安装才能包含新页面。

1. 确认 Whistle 正在运行，目标浏览器已经使用 Whistle 代理。
2. 点击「创建练习项目」，创建编号为 `mock-studio-demo` 的独立项目。已有项目会直接复用，不覆盖你的修改；项目、普通规则和组合初始均关闭。
3. 点击「打开练习配置」，启用项目总开关和当前练习所需的规则，等待代理同步。
4. 从控制台顶栏返回「功能体验」，手动发送请求，查看任务卡片和请求观察台。
5. 核对 `x-mock-source: mock-studio`、`x-mock-hit-id` 与控制台命中记录。修改规则后重新发送请求，观察变化。

页面也提供场景包下载，文件内容与 `distribution/examples/demo-package.json` 相同。手工导入后如创建了其他编号的项目，请在控制台选择该项目操作；体验页的配置快照、快捷入口和组合重置只管理固定编号的练习项目。

## 固定地址与响应契约

所有业务请求使用 `http://demo.mock-studio.test`，不提供原始服务，也不依赖真实业务系统。未被 Mock 接管时，可能发生域名解析、网络或跨域失败。页面只能报告浏览器实际读到的结果，不能单凭失败判断是哪一个开关或设置出错。

| 练习 | 请求 | 对应示例规则 |
| --- | --- | --- |
| 第一次 Mock | `GET /api/tasks` | 任务查询 |
| 延迟与失败 | `GET /api/tasks/slow`、`GET /api/tasks/error` | 慢速查询（1500ms）、失败响应（500） |
| 匹配练习 | `GET /api/tasks/search?status=todo&page=1`、调换参数顺序、改为 POST | 精确匹配、模糊匹配，两者分开启用 |
| 领取组合 | `GET /api/rewards/status`、`POST /api/rewards/claim`、再次查询 | 领取奖励流程，引用领取前、领取成功、领取后三条规则 |
| 跨域请求 | `POST /api/submit`，JSON 与 `x-demo-client` 请求头 | 跨域提交 |

演示采用本项目自定义的普通 JSON 契约，没有网关解包：任务响应为 `{ "success": true, "task": { "id": "demo-task", "title": "完成第一次 Mock", "reward": 20, "claimed": false } }`。修改 `task.title` 会直接影响任务卡片；任意其他 JSON 或非 JSON 响应仍可在观察台查看。JSON 内容不被解释为 HTML。

示例包配置来源白名单 `http://127.0.0.1:3000`、`http://localhost:3000`，允许 `content-type`、`x-demo-client` 请求头，不携带凭据。OPTIONS 预检由既有跨域逻辑处理，不推进组合、不增加业务命中；自动策略设置 `Access-Control-Max-Age: 0`，避免修改白名单后短暂复用旧的允许结果。HTTPS 与凭据跨域不属于这一版练习。

## 结果与重置的含义

- **已确认 Mock 命中**：浏览器同时读到插件来源标识和命中编号；HTTP 500 也可以是正常命中的模拟错误。
- **已收到响应，来源未确认**：有 HTTP 响应，但缺少完整证据，不能当成 Mock 成功。
- **组合顺序不匹配**：HTTP 409 且诊断码为 `COMBINATION_ORDER_MISMATCH`，显示诊断与命中编号，不冒充普通响应命中。
- **未获取到响应**：可能尚未配置 Mock，也可能是代理、网络或跨域问题。
- **请求超时／取消**：12 秒停止等待，允许用户提前取消。服务端若已选择响应，组合进度仍可能推进。

业务请求只由用户点击触发；进入页面、切换练习、刷新配置都不发送业务请求，不自动重试。管理状态在进入和完成业务请求后读取，也可手动刷新，无后台业务轮询。

「清空本页请求记录」只清空浏览器页面里的记录和卡片；「重新开始组合」经确认后重置练习项目共享进度，保留配置、开关与本页记录。组合在项目内共享，多个页面可能相互推进。刷新页面清空本页记录，不改变服务端进度。观察台最多保留最近 20 条请求。

## 自动回归

首次安装浏览器：

```bash
npx playwright install chromium --no-shell
```

日常修改后的完整回归：

```bash
npm run test:regression
```

也可分别运行 `npm run test:run`、`npm run test:api` 和 `npm run test:e2e`。后者先构建桌面 UI，再执行浏览器测试；需要可用的 `/Applications/Whistle.app`，缺失时报错，不会将跳过算作通过。

浏览器回归使用临时注册表、令牌、Whistle 数据目录和随机端口，不写入用户项目或当前桌面代理。测试启动脚本仅将管理请求地址改到本机测试转发入口，由它调用临时 API；测试域名的业务请求仍使用浏览器原生 fetch，始终经过真实 Whistle。不注册 DevTools 网络拦截，避免影响 Chromium 的预检行为。场景包只增加随机测试页面来源，不放宽真实浏览器的跨域校验。

覆盖创建并启用、修改响应、停用、加载状态、500、精确/模糊匹配、方法限制、组合成功/乱序/重置、跨域允许/拒绝、主题恢复和 390px 布局。失败保留截图与轨迹，HTML 报告在 `playwright-report/`，测试附件在 `output/playwright/results/`，均不提交。

关闭规则的用例检查不再新增命中、不再显示已确认命中，不依赖特定 DNS 错误文本。前端组件测试使用网络边界替身验证失败、取消、超时分类、凭据隔离和重置确认，不能替代真实代理回归。
