# 接口录制与资源替换（第一版）

项目工作区增加「接口录制」「资源替换」两个页签。项目总开关控制所有功能；目标浏览器需要经过 Whistle，HTTPS 请求需要完成证书配置。已运行的源码 API 服务需要重启才能加载新增路由；桌面构建命令为 `npm run build:desktop-ui`，本次源码修改不会自动更新已安装的应用。

## 接口录制与回放

1. 开启项目，进入「接口录制」，填写录制名称和接口 URL 前缀，例如 `https://api.example.com/api/`。
2. 开始录制后，在业务页面操作并复现问题。匹配范围内的请求仍访问真实后端，录制过程不模拟业务响应。范围与已启用 Mock、回放或资源替换重叠时，会提示先关闭冲突规则。
3. 停止后等待在途请求完成。按接口展开列表，可查看 URL、请求头、请求体、响应头、响应内容、状态码和耗时。gzip/deflate 响应可解压预览，存储和回放继续使用原始字节。
4. 勾选要回放、导出的接口，按需上移、下移或删除响应；关闭回放后才能整理。每个接口至少保留一条响应。
5. 导出录制包，在另一台电脑通过「导入录制包」预览并确认。导入新增一份关闭的录制，不覆盖原配置。
6. 开启回放后，按原步骤操作页面。各接口分别推进自己的响应队列，取完后保持最后一条；「重置进度」或重新开启该录制的回放开关后从头开始。项目内多个页面共享进度。

接口按 **请求方法 + 协议/域名/端口 + 路径** 分组，忽略查询参数及请求体；同 URL、同方法承载不同业务时会共用队列。第一版不做入参匹配、参数关联、域名映射、页面操作自动化，也不恢复 Cookie、本地存储或代码版本。录制耗时用于查看，回放不刻意重现耗时；并发请求按进入代理的顺序进入各自队列。

未选中的接口正常回源。单独导出录制包只包含选中接口；项目菜单导出场景包则保存整个项目，包括未选中的录制数据及资源快照。整项目导入后，项目、录制回放和资源替换均关闭。

Cookie、Authorization、Set-Cookie 头不保存到录制数据；URL 和出入参仍可能包含个人或业务敏感信息，分享前需检查。单份请求体或响应体最多 2MB，每次最多 300 条、6MB（按存储的 Base64 内容累计）。超限、请求失败/中断、304 无响应体会计入未保存数量，不返回截断响应；真实请求仍正常转发。缓存命中未经过网络的请求无法录到，必要时禁用页面缓存并重新操作。服务重启会停止录制并保留已有内容。

## 资源替换

1. 进入「资源替换」，添加名称和原资源的完整 URL。
2. 选择来源：
   - **本地文件**：选择 JS、MJS、CSS 或图片，保存选择时的文件快照，最多 2MB。原文件修改后需重新选择；分享项目场景包时快照一起保存。
   - **另一个 URL**：填写替换资源地址，例如 `http://127.0.0.1:5173/app.js`；每次匹配请求直接读取目标服务，不自动配置开发服务器的热更新。
3. 默认忽略原 URL 的查询参数，可以取消以匹配完整 URL。规则新建后关闭，打开开关再刷新业务页面。
4. 查看规则卡片的命中次数，也可在网络响应头查看 `x-mock-source: mock-studio`、`x-mock-kind: resource`。

资源替换支持 GET/HEAD，保留文件字节和 MIME 类型，并遵循项目跨域策略。跨站转发到替换 URL 时不携带原站点 Cookie/Authorization。浏览器缓存、Service Worker、资源完整性校验等仍可能影响资源加载，需要结合业务页面实际检查。

## 开发验证

使用满足项目要求的 Node 版本（本次使用 Node 24.22.2）。

- `npm run test:all`：服务端与现有界面单元回归；新增测试覆盖录制/导出/导入/独立队列/重置、压缩与二进制内容、并发与在途请求、大小限制、资源跨域、冲突拒绝及项目包兼容，并实际启动隔离 Whistle 验证录制和资源转发。
- `npm run lint`、`npx tsc --noEmit --incremental false`：静态检查。
- `npm run test:e2e`：现有六项浏览器回归。
- 在隔离控制台手动验证过创建录制、停止、两响应依次回放、末尾保持和重置，以及本地资源文件输入、保存与启用。测试使用临时 API、临时注册表和独立 Whistle，没有修改日常项目或系统代理。
