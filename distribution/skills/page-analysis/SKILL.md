# 网页接口与交互分析

以真实浏览器证据回答页面如何加载、操作触发哪些接口、参数和响应如何影响界面，以及问题发生在哪个环节。

## 工具与浏览器选择

- 优先发现并使用当前会话的 Chrome DevTools MCP 工具，不以 curl、静态脚本分析或其他浏览器自动化代替可执行的页面检查。静态分析用于补充运行时证据；MCP 不可用或缺少能力时，说明原因并选择适合的替代方式。
- 沿用当前 MCP 配置的浏览器和 Profile。遵循用户选择的浏览器和 Profile；不要关闭或修改其他浏览器实例。
- 先列出标签页，确认目标 URL、标题及页面状态；需要时新建目标页。浏览器未运行时，核实配置指向的可执行文件和用户目录后启动对应实例，避免启动空 Profile 或退出用户其他浏览器。
- 遇到登录页，让用户在该浏览器手动登录，同时分析可用的跳转前证据；登录后重新确认 URL，不把登录落地活动误当原目标页面。
- 工具名、参数以本次暴露的定义为准。重连、导航或页面重渲染后刷新 pageId、快照 uid 和请求列表；不要复用失效标识。

## 首屏基线与接口出入参

- 建立首屏基线：页面快照、截图、XHR/fetch 请求和控制台错误；涉及登录或重定向时保留导航前请求。优先读取业务请求，再区分静态资源、运营配置、埋点、监控和风控请求。
- 读取关键请求详情，解码 reqData 等表单中的 JSON，整理 method、URL、触发条件、业务入参、HTTP 状态、外层业务码、内层业务码和影响 UI 的响应字段。不可只以 HTTP 200 判断成功。
- 关联产品标识、渠道参数、页面版本、活动配置、跳转地址、列表分组与实际页面内容；区分后端返回地址和最终落地地址。
- 大响应优先保存到工具允许的输出目录后提取必要字段；先确认允许的工作区，不反复尝试被拒绝的目录。截断或导航后响应丢失时明确标注证据缺口，不将缺失部分当空数据。
- 不在报告、截图或持久化原始材料中暴露 Cookie、Token、密码、账号、设备指纹或个人信息。敏感页面优先截取相关元素或使用遮挡后的证据，必要时省略无法安全呈现的截图。

## 交互与调用时序

- 根据页面实际能力选择有代表性的入口：分类/Tab、筛选、搜索、产品详情、弹层、返回等。每次只改变一个条件，比较操作前后的快照、增量请求、响应和界面状态。
- 区分首次加载预取、点击后查询、前端本地切组、页面跳转、轮询和自动触发行为；没有新增请求不等于点击失效，出现请求也不等于本次点击触发。
- 使用请求 timing、可用时间戳或性能记录确认先后关系。请求列表顺序只能辅助定位，不能证明完成顺序、串行依赖或服务端调用关系；必要时明确“仅确认触发关系”。
- 异步流程等待可观察状态；未复现的竞争条件、未执行的错误分支和仅从代码发现的能力分别标注。不能为了补全时序而凭空推断后台 RPC 或数据库过程。
- 打开页面、切分类、查看详情和打开说明弹层属于常规分析范围，可直接推进。分析请求不自动授权购买、支付、实际领券、抽奖、关注、加自选或提交数据；按已有明确授权判断是否执行，缺少授权时完成其余可分析部分并报告未执行分支。
- 页面加载自动触发 takePrize 等疑似写入接口时，记录实际触发阶段与返回状态，避免仅凭命名认定发奖成功，也不要为补证反复触发。

## 截图与交付

- 将截图作为常规证据：至少尝试保存首屏以及代表性交互后的页面或弹层截图，问题复现时补充对应截图；页面变化很少时避免重复截图。优先用实际截图工具，不以无障碍文本快照充当图片。
- 截图应能关联操作和状态；保存到当前工具允许的目录，使用明确文件名并在交付中链接或展示。工具不可用、路径权限或隐私限制导致未保存时，说明原因。
- 默认在回复中给出：页面整体逻辑、关键接口出入参表、操作与接口及 UI 的对应关系、实际调用时序、截图证据、问题与未覆盖范围。流程复杂时补充 Mermaid 时序图或流程图；仅在用户要求文档时再创建文档。
- 结论区分“实测观察”“在线脚本/仓库静态发现”“推测或待验证”。指出证据定位信息，例如 pageId/reqid、具体操作、最终 URL；不把截图当成整个异步流程通过的证明。
- 结束时恢复本次修改的网络/设备模拟，关闭自己打开的说明弹层，说明保留的标签页和遗留状态；保留用户原有页面。
